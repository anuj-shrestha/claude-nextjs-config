description: Audit a component or page for WCAG 2.1 AA accessibility. Delegates to the a11y-auditor subagent.
argument-hint: [path/to/component-or-page]
---

Run an accessibility audit on **$ARGUMENTS** (or, if empty, the most recently edited component/page in the session).

## Steps

1. **Identify the target.**
   - If `$ARGUMENTS` is a valid path, use it.
   - If empty, look at the most recently edited `.tsx` file. If you can't determine that, ask the user which file or route to audit.
   - If the target is a route folder (e.g., `src/app/dashboard/`), audit `page.tsx` plus `layout.tsx` if it exists at the same level.
   - If the path doesn't exist, stop and report.

2. **Hand off to the `a11y-auditor` subagent** with the target. The agent will:
   - Read the target file and related files (imported components, parent layout).
   - Walk the WCAG 2.1 AA checklist.
   - Return findings classified as Critical / Serious / Minor, with file:line, WCAG criterion, and a concrete fix.

3. **Print the audit verbatim.** Don't summarize it.

## Hard Rules

- **Don't audit yourself.** Delegate to `a11y-auditor`.
- **Don't apply fixes.** A11y findings are surfaced for the user to triage.
- **If the target file uses third-party components**, remind the user that the audit covers the file as written — the audit can't verify the accessibility of compiled or external components.
